評価の方法

このページの数字は、すべて同じ1つのテスト方法で出している。モデルによって変わるのは、どのデータで学習したかと、データの分け方だけ。

共通: データの作り方

  • 1回の記録（例: 「2周目・ゾーン5・15秒」）を、0.05秒ごとのフレームにそろえる。
  • 20フレーム（約1秒）ずつまとめて特徴量（387個の数字）を作る。0.1秒ごとに1件。15秒の記録1回から約133件になる。この1件1件を当てた割合が「正解率」。
  • 基準（誰もいない状態の形）は、その日の最初に記録した基準を1回分だけ使う。学習用の empty は、各周の「誰もいない」記録を使う。
  • モデルの中身: ExtraTrees（決定木400本）、RandomForest（決定木200本）、kNN（近い5件の多数決）。どれも、記録が多い empty が有利にならないように重みをつける（kNNを除く）。

1. 周単位の交差検証（ほとんどの表の数字）

1周を丸ごとテスト用に取り分け、残りの周で学習して当てる。これを全部の周で順に行い、最後に全部の予測をまとめて採点する。

8周の場合:  テスト=1周目 / 学習=2〜8周目
           テスト=2周目 / 学習=1,3〜8周目
           …
           テスト=8周目 / 学習=1〜7周目   → 8回分の予測をまとめて採点
  • 同じ記録のフレームが学習とテストに分かれて入らないように、記録単位（周単位）で分ける。0.1秒違いのフレームはほぼ同じなので、フレーム単位でランダムに分けると、答えを見ながら当てるのと同じになってしまう。
  • 保存した .pkl は、この評価のあとで全部の周で学習し直したもの。評価の数字は、保存したモデルそのものの成績ではない。
  • コマンドは training.train --split round。
表の行学習・テストに使ったデータ周の数

2. 「3秒平均」の列

1で出た各ゾーンの確率を、同じ記録の中で直前30件（約3秒）分平均してから判定し直す。未来の値は使わない。推定の --proba-window 3 と同じ処理で、実際の推定に近づけるための数字。ただし、推定で使っている指数平滑や、確定ゾーンを決めるヒステリシス（一定時間続いたら切り替える仕組み）は入っていない。

3. 日をまたいだ評価（0.159 など）

片方の日のデータだけで学習し、もう片方の日を当てる（--split date）。基準をどちらの日のものにするかも、2通り試した。これだけは「前の日のモデルを次の日に使う」という実際の使い方と同じ条件で、結果はでたらめと同じだった。

4. 学習曲線

1と同じく1周をテスト用に取り分ける。学習には、残りの周を番号順に並べて先頭から k 周だけを使い、k を1ずつ増やす。「学習5周でそろえた比較」（扇形 0.712、4つ角 0.754）は、この k=5 の値。周の数と同時に「どの周が入ったか」も変わるので、伸び方はでこぼこになりやすい。

5. あとから追加した確認（3日目）

  • 時間順の評価: 前の周だけで学習して、後の周を当てた（例: 学習1〜3周 → テスト4〜6周で 0.671）。
  • 記録ごとの集計: 各記録が何割当たったかを数えた（54回のうち14回は正解0）。
  • リアルタイム推定の集計: estimate.csv の確定ゾーンの時間と確率を集計した。正解の記録がないので、正解率は出せていない。

限界1〜4のどれも、収集のときに記録したデータどうしを当て合っているだけ。案内どおりの場所と姿勢で、移動中は記録していないデータ。テストする周の前後の周も学習に入る。そのため、リアルタイムで立ったときの当たり方は測れていない（扇形のゾーン1は評価で 1.00 だったが、リアルタイムでは反応しなかった）。

6. これから: 正解付きのテスト用データで採点する

学習が終わったあとで、音声ガイドの収集をもう一度行い、テスト用として別のフォルダに保存する。指示された場所が正解として記録されるので、保存したモデルをそのまま当てれば採点できる。学習には使わないので、実際の使い方に一番近い評価になる。

$PY -m collection.plan --serial COM3 --zones config/zones_fan.json --out-dir data/d3_fan_20261012/test1 \
    --rounds 2 --zone-duration 15 --empty-duration 20 \
    --postures "ゾーンの真ん中に立ってください|ゾーンの真ん中に座ってください"
$PY -m training.score --model data/models/d3/et.pkl --data data/d3_fan_20261012/test1/calib.jsonl

--train は付けない（テスト用データで学習し直すと、採点の意味がなくなる）。--baseline data/d3_fan_20261012/test1/baseline.jsonl を足すと、基準をテスト時のものに替えて採点できる（基準の取り直しで直るかの確認）。

わかったこと

  • 姿勢を絞って各2周にしたのが一番効いた（0.627 → 0.831）。1日目は姿勢が1周ずつで、評価のたびに「学習で見ていない姿勢」を当てていた。
  • どのデータでも ExtraTrees > RandomForest > kNN。ExtraTreesを使い続ける。
  • 1日目のデータを足すと、かえって下がる（0.831 → 0.746）。2日目だけの周（6〜8周目）の当たり方も変わらない。
  • 2日目の学習曲線は7周 → 8周でも macro-F1 が +0.024 伸びている。周を増やす余地はまだある。
  • 扇形（3日目）も ExtraTrees が一番良く、周単位の評価では4つ角より低い。ただしリアルタイム推定では、この評価ほど当たらなかった（3日目）。周単位の評価は、実際に使ったときより甘く出る。

ゾーンごとの当たり方

ExtraTreesの再現率（そのゾーンにいたときに正しく当てた割合）。上が奥、下が手前（RX側）。色が濃いほど高い。赤枠は0.70未満。各ゾーンの記録は1日に5〜8回しかなく、1回分の記録がまるごと外れることも多い（3日目は1回分＝約0.17）。ゾーンごとの値は誤差が大きいので、0.1〜0.2程度の差で良し悪しを決めない。

注意この値は、リアルタイムでゾーンを見分けられることを示していない。 扇形のゾーン1は 1.00 だが、リアルタイム推定ではゾーン1に立っても反応しなかった。これは「収集した記録どうしを当て合った」ときの値にすぎない。

記録の特徴量を比べると、同じゾーンに別の時に立った記録どうしの差（扇形 17.4、4つ角 16.5）が、隣り合うゾーンの差（扇形 20.1、4つ角 16.9）とほとんど変わらない。同じゾーンに立ち直すだけで、隣のゾーンに移ったのと同じくらい電波が変わる。この差は時間がたつほど大きくなるわけではない（扇形: 記録3回以内の間隔で 16.8、16回以上離れると 17.6）。そのため、ずれの主な原因は時間ではなく、立つたびの位置・姿勢・向きの違いと考えられる。位置を見ずに「何周目の記録か」を当てても 0.29 だった（でたらめなら 0.17）。時間の情報も少しは入っているが、主な原因ではない。

同じ日の中のずれ（10/03の記録で0.05〜0.11）より、ずっと大きい。数cmの位置・向き・高さの違いや、部屋の中の物の配置で、CSIの形は大きく変わる。1日目のあとに機材を片付けて置き直したのが原因と考えるのが自然。

収集中に気をつけること

  • RX・TXの位置・高さ・向きをメジャーで測ってメモし、写真を撮る
  • 床にテープでゾーンの境界を貼り、体は境界から15〜20cm内側に置く
  • TXのモバイルバッテリーを満充電にする
  • empty中は部屋の外か、領域から2m以上離れた毎回同じ場所に立つ
  • 収集者以外は部屋の外へ。ドア・椅子・PCの位置を収集中は動かさない
  • ゾーンの中では小さく動き続ける（完全な静止も、歩き回るのも避ける）

3日目: 扇形の配置（2026-10-12、済）

RXを手前の辺の中央の少し外に置き、TXを奥の辺に3台並べる。中央のリンクは中央の列（2・5・8）を縦に通る。左右のリンクは斜めに走り、手前ではゾーン2を通ってから、左は1の角・4・7、右は3の角・6・9を通る。ゾーン2は3本すべてが通り、ゾーン1・3は角をかすめるだけ。

結果周単位の評価では、ExtraTreesで正解率 0.731、macro-F1 0.704（4つ角は 0.831 / 0.822）。学習に使う周をそろえて5周で比べると、macro-F1 は扇形 0.712、4つ角 0.754。ただし、ここから「4つ角のほうが良い」とは言えない。周の数・姿勢の配分が違い、ゾーンごとの値も誤差が大きいため。さらにリアルタイム推定では、周単位の評価ほど当たらなかった（下の「リアルタイム推定」）。配置はまだ決められない。

わかったこと

  • 誤りのほとんどは、1回分の記録がまるごと外れたもの。 ゾーンの記録54回のうち14回は、正解が1件もなかった。その多くは、記録の全部を同じ別のゾーンと判定していた（例: 3周目のゾーン7 → すべて empty、5周目のゾーン6 → すべて9）。境界で少しずつ取り違えているのではない。記録1回ごとに電波のパターンが違い、学習した記録と似ていないと丸ごと外れる。
  • リンクの本数では説明できない。 3本すべてが通るゾーン2が最も低く（0.30）、ほとんど通らないゾーン1が最も高い（1.00）。外れた記録はゾーン3・6・7・9にもある。「中央の列は1本のリンクしか通らないから苦手」という以前の説明は誤り。
  • 周ごとの正解率: 真ん中に立つ 0.901 / 0.901、ずらして立つ 0.799 / 0.470、真ん中に座る 0.664 / 0.658。立つ姿勢でも低い周がある。
  • 前の周だけで学習して次の周を当てると、0.689 → 0.414 → 0.887 → 0.466 → 0.658 と上下する（学習1〜5周）。周を増やせば上がる、とは言えない。周ごとのばらつきのほうが大きい。

data/d3_fan_20261012/estimate.csv から集計した。収集が終わってから15〜25分後の推定。正解（その時どこにいたか）は記録していないので、当たった割合は計算できない。

モデルは、リアルタイムの電波を学習したどのゾーンともあまり似ていないと見ている。誰もいない時間があったのに empty が出なかったのなら、評価の empty 再現率 1.000 は実際には当てはまらない。

評価がリアルタイムより甘く出る理由

  • 同じゾーンに立ち直すだけで、隣のゾーンに移ったのと同じくらい電波が変わる。 記録の特徴量の差は、同じゾーン・別の時で 17.4、隣り合うゾーンで 20.1 と、ほとんど変わらない（4つ角は 16.5 と 16.9）。周単位の評価では、テストする記録に似た記録が学習側にたまたまあれば当たり、なければ丸ごと外れる。リアルタイムで立ったときの電波が、学習したどの記録とも似ていなければ当たらない。
  • 時間によるずれもあるが、主な原因ではない。empty の記録を最初の回と比べると、ずれは 0.30〜0.50 で、おおむね後の周ほど大きい（1回の記録の中の差は 0.11）。ただし同じゾーンの記録どうしの差は、時間が離れてもほとんど増えない（記録3回以内の間隔 16.8、16回以上 17.6）。位置を見ずに「何周目か」を当てても 0.29（でたらめなら 0.17）。
  • 前の周だけで学習して後の周を当てると（学習1〜3周 → テスト4〜6周）0.671 で、周単位の評価（0.731）より低い。
  • 収集のときは、案内どおりゾーンの中心付近にいて、ゾーン間の移動中は記録していない。リアルタイムでは移動中も判定する。

わかったこと今の特徴量では、ゾーンの違いが「立つたびの違い」に埋もれている。周単位の評価の数字（0.73〜0.83）は、リアルタイムの当たり方を表していない。配置の比較より先に、正解付きのテスト用データで実際の当たり方を測り、ゾーンの数・大きさ・特徴量を見直す必要がある。2日目（4つ角）も、10/11のリアルタイム推定で確率がばらけていた（touchdesigner/README.md）ので、扇形だけの問題ではない。

本番の手順

配置はまだ決まっていない（3日目の結果だけでは決められない）。機材を置き直すと前のモデルは使えないので、会場に設置してから収集する。また、今の方法ではリアルタイムで当たらないことがわかったので、本番の前に、正解付きのテスト用データで実際の当たり方を確かめる（training.score）。

  1. 機材を設置し、以後は動かさない

    テープで固定し、位置・高さ・向きを写真に残す。湯量・水位・物の配置も本番と同じにする。

  2. 収集する

    2日目と同じ計画（約42分）。時間がなければ周を減らす。どの姿勢も2周ずつ入るよう、--postures の種類を周の数の半分にする。

    周の数時間姿勢
    8約42分4種類（2日目と同じ）
    6約32分3種類（例: 真ん中に座る / ずらして座る / 真ん中に立つ）
    4約21分2種類（例: 真ん中に座る / ずらして座る）
  3. その日のデータだけで学習する

    --train で自動学習したモデルを data/models/dN/et.pkl にまとめ、本番に使う（手順は3日目の5と同じ）。

  4. 推定を起動する 
    $PY -m localization.estimate --serial COM3 --model data/models/dN/et.pkl --osc 127.0.0.1:9000 --remote

    本番までに機材が動いてしまったら、2からやり直す。
