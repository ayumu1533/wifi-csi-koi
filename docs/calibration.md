# キャリブレーション手順（ゾーン分類）

浴槽内の各ゾーンでCSIサンプルを収集し、ゾーン分類モデル（RandomForest）を学習するまでの手順。
ゾーンは「人がいない（empty, ID 0）」＋浴槽を分割した領域で、`server/config/zones.json` で定義する。

## 事前準備

1. **ゾーンを決める**: `server/config/zones.json` に浴槽サイズ（`tub_size`）、センサー位置（`sensors`）、
   ゾーン（`id` / `name` / `center` / `rect`）を定義する。単位はメートル。
   - ID 0 は `empty`（`center`・`rect` は `null`）。在/不在を演出に使うため必須
   - 現在の既定は3m×3mの領域を1m角で3×3に分割した9ゾーン（ID 1〜9、前列→奥列・左→右の順）＋empty。
     ESP32の振幅CSIは分解能が粗いため、細かく分けすぎると分類精度が落ちる。
     センサー台数が少ないうちは2×2など粗いゾーンから始めてもよい
   - 浴槽の内寸を実測し、座標系の原点・向きを `zones.json` に合わせる
   - ゾーン数や配置はコードに書かれておらず、`zones.json` を編集するだけで変えられる（変えたら再収集・再学習）
2. **使うTXを決める**: CSIは「csi_tx(TX) → csi_rx(RX)」の電波経路で測る。
   csi_rxを領域の角 (0,0) に置き、csi_txを他の角に置く（`zones.json` の `rx` と `tx` に座標を定義）。
   - TX ID 1=(3,0)（手前の辺）、ID 2=(0,3)（左の辺）、ID 3=(3,3)（対角線）
   - 実際に使うものだけ `"enabled": true` にする。収集・学習・仮想センサーは enabled なTXだけを使う。
     一時的に変えたいだけなら各コマンドに `--sensors 3` のように付ければ zones.json を編集せずに上書きできる。
   - **台数を変えたら再収集・再学習が必要**（特徴量の次元が変わるため）。
   - 動作テスト（2台運用）: csi_tx ×1（ID 3、対角線のみ）＋ csi_rx ×1。ID 1,2 は `enabled: false`。
     この場合、経路が近い 1,5,9 以外は判別が難しい
3. **機材配置**: csi_rxを (0,0) に、csi_txを上記の座標に設置する。csi_txは電源（モバイルバッテリー等）のみ。
   csi_rxだけをPCにUSB接続する（PCのWiFi接続・IP設定は不要）。
4. **疎通確認**: csi_rxのCOMポート番号をデバイスマネージャーで確認し、
   `python -m csi_receiver.receiver --serial COM3` で、enabled な全TXのパケットが
   約100Hzで届いていることを確認する（enabled でないTXのパケットは収集・学習時に無視される）。
   `--serial` を省略するとUDP受信になる（`tools.simulate` 用）。

以降のコマンドは `server/` ディレクトリで実行する。

## 収集手順

### 1. empty（ゾーン0、浴槽が空の状態）

人が浴室にいない（少なくとも浴槽から十分離れた）状態で30秒程度記録する。**3セッション以上**収集する。

```bash
python -m collection.collect --serial COM3 --zone 0 --delay 5 --duration 30 --out data/empty.jsonl
```

`--baseline data/empty.jsonl` として学習に渡すと、以下のように使われる:

- **先頭セッション**: 浴槽の固定的な反射パターン（ベースライン）の算出専用。学習時に差し引くことで人体による変化を強調する
- **残りのセッション**: ゾーン0の学習データ

ベースライン算出と学習に同じセッションを使うと評価が甘くなるため、このように分けている。
**湯量や水位を変えたらベースラインも取り直すこと。**

### 2. 各ゾーンの収集

各ゾーン（ID 1〜）について、そのゾーン内に人が入った状態で記録する。

```bash
python -m collection.collect --serial COM3 --zone 1 --duration 10 --out data/calib.jsonl
python -m collection.collect --serial COM3 --zone 2 --duration 10 --out data/calib.jsonl
# ... 全ゾーン
```

- **ゾーン内で位置や姿勢を少しずつ変えながら収集する**（座る・足を伸ばす・体の向きを変える等）。
  1点で静止した収集だけだと、ゾーン内で起こりうる振幅のばらつきを学習できず、実運用で精度が落ちる
- **各ゾーン2セッション以上**収集する（1回の実行＝1セッション）。評価はセッション単位で学習側とテスト側を
  分けるため、1セッションしかないゾーンは評価できず、警告のうえ評価がスキップされる。
  位置・姿勢・時間帯を変えて取ると評価が現実に近づく
- `--delay`（既定3秒）はコマンド実行から記録開始までの待ち時間。位置につくのに使う
- 記録終了時にセンサーごとのパケット数とレートが表示される。
  特定センサーだけ極端に少ない場合は設置や電波状況を確認する
- 収集日もレコードに保存される（`--split date` での評価に使う）

### 3. 学習と評価

```bash
python -m training.train --data data/calib.jsonl --baseline data/empty.jsonl \
    --algo rf --model-out data/model.pkl
```

- 評価は**セッション単位**のleave-one-group-out。10ms間隔のほぼ同一フレームが学習・評価に混ざる
  データリークを避けるため、フレーム単位のランダム分割はしていない
- 表示される指標: 正解率、macro-F1、ゾーンごとの再現率、混同行列。混同行列は
  `<model-out>.confusion.csv`（`--report-out` で変更可）にも保存される
- 再現率が低い・混同行列で他ゾーンと混ざっているゾーンは、追加収集して再学習する
- `--algo knn` と比較し、良い方を採用する（既定は `rf`）
- `--split date` で収集日単位の評価ができる（環境変化への頑健性評価。2日以上のデータが必要）
- 使ったデータファイル・セッション数・乱数シード（`--seed`）・ライブラリのバージョンは
  モデルと評価ログに記録される

### 4. 動作確認

```bash
python -m localization.estimate --serial COM3 --model data/model.pkl
```

実際に浴槽内を移動し、表示されるゾーンが追従するか確認する。境界でのチャタリングが
気になる場合は `--zone-threshold` / `--hysteresis-frames` / `--proba-ema` を調整する
（詳細は [server/README.md](../server/README.md) の「調整すべきパラメータ」）。
TouchDesignerへ送る場合は `--osc 127.0.0.1:9000` を付ける（仕様は [protocol.md](protocol.md)）。

## 再キャリブレーションが必要になるタイミング

CSIは環境の変化に敏感なため、以下の場合は再収集・再学習が必要:

- センサーやAPの位置・向きを動かした
- ゾーン定義（`zones.json`）を変えた
- 湯量・水位が大きく変わった
- 浴室内の大きな物（風呂蓋、椅子など）の配置が変わった
- 推定精度が明らかに落ちたと感じたとき
