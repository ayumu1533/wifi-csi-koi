# データ収集・学習計画（2026-10〜）

> 読みやすい版は [collection_plan.html](collection_plan.html)（ブラウザで開く）。内容を変えるときはHTML版を正とする。

精度を上げるために、次の3つをまとめて行う計画。コマンドはこのとおりに打てば進むように書いてある。

1. **本番の姿勢に絞り、同じ姿勢を複数周取る**
2. **別の日にもう1セット取る**（日によって環境が変わっても強いモデルにする）
3. **配置を扇形に変えて比べる**（4つ角の配置では、ゾーン6・8をどのリンクも通らない）

手順の細かい説明は [runbook.md](runbook.md)、結果は [results.md](results.md) に書く。
データとモデルの置き場所は `server/data/README.md`。

> **2日目の結果（2026-10-11）で計画を見直した**（詳細は [results.md](results.md)）
>
> - 1の効果は大きかった（正解率 0.627 → 0.831）。
> - 2はうまくいかなかった。前の日のモデルで次の日を当てると正解率0.1前後で、でたらめと同じ。基準を取り直しても直らない。機材を置き直すと電波のパターンがまったく変わるため。1日目と2日目のデータを合わせても、2日目の精度は上がらなかった。
> - そのため、**本番は「設置したら動かさない → その場で収集 → 学習」で行う**。別の日のデータは、機材を一度も動かしていない場合だけ合わせる。

| -- | ---- | ---- | -------------- | ------ |

- 収集データは日ごとのフォルダに分ける（`--out-dir`）。データが混ざらず、日ごとの評価もしやすい。
- モデルは `data/models/<学習に使ったデータ>/<アルゴリズム>.pkl` に置く（例: `data/models/d2/et.pkl`）。
- 2日目と3日目は**同じ計画（周の数・秒数・姿勢）**で取る。条件をそろえないと、配置を変えた効果を比べられない。
- 以前の予定にあった「4日目に扇形でもう1日取る」はやめる。日をまたいだデータは役に立たないので、その分を本番の当日の収集に回す。

## 収集の計画（2日目以降、毎回共通）

### 周の数と時間の配分

| 項目 | 1日目 | 2日目以降 | 理由 |
| ---- | ----- | --------- | ---- |
| 周の数 | 5 | **8** | 学習曲線が4周でもまだ伸びていた（3周→4周で macro-F1 +0.043） |
| ゾーン1回の記録 | 20秒 | **15秒** | 1回を長くするより周を増やすほうが条件のばらつきを学べる。ゾーンあたりの合計は 100秒 → 120秒 で増える |
| empty 1回の記録 | 30秒 | **20秒** | emptyは毎周あるので、合計は十分（8周 × 20秒 = 160秒） |
| 移動の待ち時間 | ゾーン8秒、empty 12秒 | 変えない | |
| 合計時間 | 52回・約32分 | **82回・約42分** | 1日目より約10分長いだけ |

### 姿勢（周ごと）

本番の入浴者は**座っている時間が長い**と考えて、座る姿勢を多めにする。4種類を2周ずつ回す。

| 周 | 姿勢 |
| -- | ---- |
| 1, 5 | ゾーンの真ん中に座る |
| 2, 6 | ゾーンの中で位置をずらして座る |
| 3, 7 | ゾーンの真ん中に立つ |
| 4, 8 | 向きを変えて座る |

- どの姿勢も2周あるので、周を1つ抜いて評価しても、同じ姿勢がもう1周学習に残る（1日目は姿勢が1周ずつしかなく、評価が厳しすぎた）。
- 本番の姿勢が違う場合（立っている時間が長い、など）は、`--postures` の中身を本番に合わせて入れ替える。**2日目と3日目は同じにすること。**

## 2日目（2026-10-11）：4つ角の配置

配置は1日目と同じ（RX (0,0)、TX1 (3,0)、TX2 (0,3)、TX3 (3,3)）。`config/zones.json` はそのまま使う。

### 0. 始める前に（5分）

- [ ] RX・TXが1日目と同じ位置にある。**アンテナの高さ・向きをメジャーで測ってメモし、写真を撮る**（後日、扇形と比べたり4つ角に戻したりするときに再現するため）
- [ ] 床にテープでゾーンの境界を貼る（境界から15〜20cm内側に体を置けるように）
- [ ] TXのモバイルバッテリーを満充電にする
- [ ] empty中に立つ場所を決める。**部屋の外**、または領域から2m以上離れた場所に毎回立つ（1日目はemptyがゾーン3と誤りやすかった）
- [ ] 収集者以外は部屋の外へ。ドア・椅子・PCの位置を、収集中は動かさない

### 1. 疎通確認（Git Bash）

```bash
cd server
PY=.venv/Scripts/python.exe
$PY -m csi_receiver.receiver --serial COM3
```

`sensor1`〜`sensor3` の3台とも、`n` が毎秒約80〜100ずつ増えればOK。`Ctrl+C` で止める。

### 2. 収集（約42分）

計画を確認してから始める。

```bash
$PY -m collection.plan --list --out-dir data/d2_corner_20261011 \
    --rounds 8 --zone-duration 15 --empty-duration 20 \
    --postures "ゾーンの真ん中に座ってください|ゾーンの中で位置をずらして座ってください|ゾーンの真ん中に立ってください|向きを変えて座ってください"
```

最後に `合計 82 回、約42分` と出ればよい。`--list` を外して `--serial COM3 --train` を付けて開始する。

```bash
$PY -m collection.plan --serial COM3 --out-dir data/d2_corner_20261011 \
    --rounds 8 --zone-duration 15 --empty-duration 20 \
    --postures "ゾーンの真ん中に座ってください|ゾーンの中で位置をずらして座ってください|ゾーンの真ん中に立ってください|向きを変えて座ってください" \
    --train
```

- スマホのリモコンで「開始」を押すと始まる。
- `--train` を付けたので、収集が終わると学習（ExtraTrees・RandomForest）と学習曲線まで自動で行い、正解率を読み上げる。ログとモデルは `--out-dir` のフォルダに保存される（`train_et.log`、`train_rf.log`、`learning_curve.txt`、`model.pkl`、`model_rf.pkl`）。終わったら `data/models/dN/` に `et.pkl`・`et.log` のような名前で移す（下の「3.0 モデルの置き場所」）。
- 途中で止まった場合は、表示されるステップ番号から `--start-from N --append` を付けて同じコマンドで再開する。

### 3. 学習・評価（2026-10-11 済。結果は [results.md](results.md)）

#### 3.0 モデルの置き場所

`--train` を使わずに手で学習するときは、次のように最初から `data/models/` に保存する。

```bash
D2=data/d2_corner_20261011
for algo in et rf knn; do
  $PY -m training.train --data $D2/calib.jsonl --baseline $D2/baseline.jsonl \
      --algo $algo --split round --window 20 --stride 2 --model-out data/models/d2/$algo.pkl > data/models/d2/$algo.log 2>&1
done
$PY -m training.learning_curve --data $D2/calib.jsonl --baseline $D2/baseline.jsonl > data/models/d2/learning_curve.txt 2>&1
```

#### 3.1 2日目だけで評価する

`data/models/d2/et.log` を見る。

- 結果: 正解率0.831、macro-F1 0.822（1日目のETは0.627 / 0.608）。姿勢を絞って各2周にした効果が大きかった。
- 学習曲線（`data/models/d2/learning_curve.txt`）は7周→8周で macro-F1 +0.024。まだ伸びている。

#### 3.2 日をまたいで評価する

1日目と2日目のデータを合わせ、片方の日で学習してもう片方の日で当てる。

```bash
$PY -m training.train --data data/d1_corner_20261004/calib.jsonl $D2/calib.jsonl --baseline $D2/baseline.jsonl \
    --algo et --split date --window 20 --stride 2 --model-out data/models/cross_date/et.pkl > data/models/cross_date/et.log 2>&1
```

- 結果: 正解率0.128（でたらめと同じ）。基準をその日のものにしても0.1前後のまま。機材を置き直したことで、電波のパターンが変わったと考えられる。

#### 3.3 両日のデータで学習する

```bash
$PY -m training.train --data data/d1_corner_20261004/calib.jsonl $D2/calib.jsonl --baseline $D2/baseline.jsonl \
    --algo et --split round --window 20 --stride 2 --model-out data/models/d1+d2/et.pkl > data/models/d1+d2/et.log 2>&1
```

- 結果: 正解率0.746。2日目だけ（0.831）より低く、2日目の周の当たり方も変わらなかった。**本番用には `data/models/d2/et.pkl`（2日目だけ）を使う。**

#### 3.4 実際に動いて確かめる

```bash
$PY -m localization.estimate --serial COM3 --model data/models/d2/et.pkl --remote \
    --out data/d2_corner_20261011/estimate.csv
```

- 2日目の収集のあと、**機材を動かしていない**ときだけ意味がある。動かした場合は、その日に収集し直す。
- 各ゾーンに座って、スマホの表示が正しいゾーンになるまでの時間と、境界で揺れないかを見る。特に今の苦手な **ゾーン1（手前の左）と5（真ん中の中央）** を確かめる（RX〜TX3の対角線の上で取り違えやすい）。

### 4. 記録

[results.md](results.md) の「2026-10-11 2日目」に記録済み。3.4 で気づいたことがあれば追記する。

## 3日目（2026-10-12、済）：扇形の配置

> **結果（詳細は [results.md](results.md)）**
>
> - 実際の収集は時間を減らして **6周**（62回・約32分）。姿勢は「真ん中に立つ / ずらして立つ / 真ん中に座る」を2周ずつ（立つ4周・座る2周）にした。
> - ExtraTrees: 正解率 0.731、macro-F1 0.704、empty 1.000（3秒平均で 0.747 / 0.721）。RandomForest は 0.660、kNN は 0.511。
> - 学習に使う周をそろえて5周で比べると、扇形 0.712、4つ角 0.754（macro-F1）。差は0.04で、周の数・姿勢の違いや誤差で説明できる範囲。
> - ゾーンごとの値は誤差が大きい（1回分の記録がまるごと外れると約0.17動く）。リンクの本数と当たり方は対応しなかった。
> - **リアルタイム推定では、評価ほど当たらなかった。** 約10分のうち60%がゾーン6で、empty は一度も出なかった。ゾーン1（評価では 1.00）に立っても反応しなかった。同じゾーンに立ち直すだけで、隣のゾーンに移ったのと同じくらい電波が変わっていて、ゾーンの違いが埋もれている。
> - **配置はまだ決められない。** 先に、正解付きのテスト用データ（`training.score`）で実際の当たり方を測る。
> - 実際の設定ファイルは `server/config/zones_fan.json`、モデルは `data/models/d3/{et,rf,knn}.pkl`。

### 配置

RXを手前の辺の中央の少し外に置き、TXを奥の辺に3台並べる。中央のリンクは2・5・8を縦に通る。左右のリンクは斜めに走り、手前ではゾーン2を通ってから、左は1の角・4・7、右は3の角・6・9を通る（3日目に確認して訂正）。

```text
  y=3  TX2(0,3)   TX3(1.5,3)   TX1(3,3)
         ╲  7   │   8   │   9  ╱
          ╲     │       │     ╱
           ╲ 4  │   5   │  6 ╱
            ╲   │       │   ╱
             ╲1 │   2   │ 3╱
  y=0 ────────── RX(1.5,-0.3) ──────────
```

- **アンテナの高さ**: 本番で座ったときの胸の高さにそろえる（RX・TXとも同じ高さ）。4つ角との違いが配置だけになるよう、2日目と同じ高さにするのでもよい。どちらにしたかをメモする。
- TXのファームウェア（TX ID）は書き換えなくてよい。置く場所を変えるだけ。

### 設定ファイル

`config/zones.json` は4つ角用として残し、扇形用のファイルを別に作る。座標は表示・設置の目安用で、推定には使われない。

`server/config/zones_fan.json`（`zones.json` をコピーし、`rx` と `tx` だけ変える）:

```json
  "rx": {"pos": [1.5, -0.3]},
  "tx": [
    {"id": 1, "pos": [3.0, 3.0], "enabled": true},
    {"id": 2, "pos": [0.0, 3.0], "enabled": true},
    {"id": 3, "pos": [1.5, 3.0], "enabled": true}
  ],
```

### 収集・学習

2日目と同じ手順で、`--zones config/zones_fan.json` を付け、保存先を変える。

```bash
$PY -m collection.plan --serial COM3 --zones config/zones_fan.json --out-dir data/d3_fan_YYYYMMDD \
    --rounds 8 --zone-duration 15 --empty-duration 20 \
    --postures "ゾーンの真ん中に座ってください|ゾーンの中で位置をずらして座ってください|ゾーンの真ん中に立ってください|向きを変えて座ってください" \
    --train
```

- 扇形のデータは、4つ角のデータと**混ぜて学習しない**（配置が違うと電波のパターンがまったく違う）。

### 4つ角と比べる

3日目の `train_et.log`（`data/models/d3/et.log` に移す）と、2日目の `data/models/d2/et.log` を比べる。どちらも「その日の中」の評価で条件もそろっているので、差は配置の違いと考えてよい（日をまたいだ評価は、配置の比較には使えない）。

| 見るところ | 扇形を採用する目安 |
| ---------- | ------------------ |
| macro-F1 | 4つ角（0.822）より上 |
| ゾーン1・5の再現率 | 4つ角（0.622・0.646）より明らかに上（2日目の苦手ゾーン。対角線の上で取り違えていた） |
| ゾーン6・8の再現率 | 4つ角（0.836・0.851）と同程度以上 |
| empty再現率 | 4つ角と同程度以上 |
| 実際に動いたとき（3.4と同じ確認） | 追従・揺れが4つ角と同じか良い |

- **扇形が良い** → 本番も扇形にする。
- **4つ角が良い** → 本番は4つ角にする。
- どちらの場合も、本番の会場に設置したあとで収集し直す（下の「本番の直前」）。3日目までのモデルは、そのままでは使えない。

## 本番の直前

機材を置き直すと、前のモデルは使えない（2日目の結果）。本番の会場に設置したら、次の順で行う。

1. 機材を設置し、**以後は動かさない**（テープで固定し、位置・高さ・向きを写真に残す）。湯量・水位・物の配置も本番と同じにする
2. 2日目と同じ計画で収集する（約42分）。時間がなければ周を減らす（`--rounds 6` で約32分、`--rounds 4` で約21分）。どの姿勢も2周ずつ入るように、`--postures` の種類を周の数の半分にする
3. その日のデータだけで学習し、`data/models/dN/et.pkl` を本番に使う
4. 本番までに機材が動いてしまったら、2からやり直す
